# 修复多终端运行时的工作台输入停顿

用隔离 VS Code 启动三个测试 Bot，通过 AIO 派工接口分别启动 7、12、17 个真实 Claude Code 工作进程。各工作进程接收相同的 CST 分析任务，使用读取和搜索工具。测试记录输入事件和界面帧间隔，报告不包含模型返回的源码或实车数据。

原版实测的最长按键响应分别为 26.665 秒、23 毫秒、107.175 秒。最长帧间隔分别为 34.524、32.975、107.206 秒。15 终端场景的按键未撞上最长画面停顿。三档成功采集的按键都录入，未观察到输入框禁用或焦点丢失。模拟负载对照表明，持续终端输出是能够独立验证的压力来源，不能仅凭真实任务中的孤立长停顿判定唯一根因。

宿主以 32 毫秒窗口合并输出，保留单终端顺序并在退出事件前送出剩余输出。后台标签完成启动握手后暂存输出，切回再交给 xterm。每个隐藏终端缓冲约 256 Ki 个字符，溢出时保留较新的输出并显示提示。

0.1.58 三档复测各有 100 次按键全部录入，最长响应分别为 375、306、89 毫秒。最长帧间隔分别为 1.417、0.558、0.475 秒。采样窗口和模型输出量不同，这些是单轮极值。性能复测未等待所有 CST 分析完成。72 项自动测试与真实 VS Code 的 Bot 派工、跨标签输入路由测试通过。
