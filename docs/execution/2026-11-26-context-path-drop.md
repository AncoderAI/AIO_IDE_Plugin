# 0.1.5 拖入文件和文件夹路径

工作台接收 Explorer 的 URI 与路径列表。扩展宿主使用工作区和文件类型元数据核对引用，返回绝对路径。拖放处理不读取文件正文，不遍历目录，也不读取拖动协议中的编辑器文档内容。

工作台对话框在光标处插入引用，内嵌终端沿用 xterm 的粘贴输入。原生集成终端使用 VS Code 自带的路径拖放。

Windows 原生终端的真实鼠标验收覆盖一个文件和一个子目录。两次拖放都在 Enter 前保持输入状态，Enter 后测试 CLI 只收到对应的绝对路径。26 项自动测试通过，包含路径编码、中文、空格、混合引用与控制字符检查。

在 VS Code 1.147 中复现了 Explorer 拖动未进入 Webview 的宿主问题。通过调试协议向工作台投递夹具 URI 后，真实输入框只包含路径，没有测试正文。另在 Extension Host 中执行 Explorer 引用命令，验证多选文件与文件夹能插入同一草稿。原生 TreeView 提供独立于跨 Webview 拖放的入口。直接跨 Webview 的物理拖放未在该版本验收通过。[VS Code 上游问题](https://github.com/microsoft/vscode/issues/339036)
