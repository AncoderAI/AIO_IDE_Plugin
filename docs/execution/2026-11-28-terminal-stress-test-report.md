# AIO 多终端并发压力测试报告

测试版本为 AIO 0.1.57 和修复版 0.1.58。修复提交为 `07ac542`。

## 测试范围

在隔离的 Windows VS Code 中，每档使用 3 个测试 Bot 通过 AIO 的派工接口启动工作终端。10、15、20 个终端分别包含 7、12、17 个真实 Claude Code 工作进程。每个工作进程接收同一项 CST 只读分析任务，涉及实车数据、约 50 Hz 振荡及约 106 毫秒的手力响应延迟。测试测量的是 AIO 底部对话框的输入响应，采样期间各工作进程仍在执行。报告只记录性能数据。

- **按键响应**是测试驱动发送一次按键并收到调用返回的耗时。另用输入事件确认字符进入底部文本框。
- **画面停顿**是 Webview 连续动画帧之间的最长间隔。按键未必正好发生在最长停顿期间。

## 结果

| 终端总数（Bot + 工作终端） | 最长按键响应 0.1.57 → 0.1.58 | 最长画面停顿 0.1.57 → 0.1.58 | 修复版按键录入 |
| --- | ---: | ---: | ---: |
| 10（3 + 7） | 26.665 秒 → 375 毫秒 | 34.524 秒 → 1.417 秒 | 100 / 100 |
| 15（3 + 12） | 23 毫秒 → 306 毫秒 | 32.975 秒 → 558 毫秒 | 100 / 100 |
| 20（3 + 17） | 107.175 秒 → 89 毫秒 | 107.206 秒 → 475 毫秒 | 100 / 100 |

15 终端的旧版测试按键未碰到最长画面停顿。三档有效采样中，按键最终录入，未观察到输入框禁用、消失或失焦。表中为单轮极值，模型输出量与采样时长存在差异。性能复测在取得输入数据后结束，未等待所有 CST 任务完成。

## 发现的问题

旧版后台标签虽然不可见，每个终端的输出仍经过后台服务和扩展宿主，送进 Webview 的 xterm 解析。当多个工作终端集中输出时，消息处理和终端解析会占用底部输入框所在的渲染线程。表现是界面暂时停住，恢复后字符陆续出现。

模拟负载对照使用相同数量的 Bot 和工作终端，保留计算、磁盘读写及 Bot 通信，只停掉工作终端日志。在 10、15、20 终端下，最长按键响应从 463、967、2,671 毫秒降为 13、22、36 毫秒。这确认了输出链路会放大卡顿。真实任务中秒级停顿还可能受主机资源竞争影响，本次没有分离各进程的 CPU 和磁盘贡献。

## 修复与验证

1. **合并宿主发往 Webview 的输出。** 用约 32 毫秒的窗口按终端合批，保持各终端内部的输出顺序。收到退出事件时先送出已缓存的输出。[宿主实现](../../src/workbench.js)
2. **后台标签延后解析。** 保留 CLI 启动阶段的终端交互。完成启动后，后台输出先暂存，回到该标签时再交给 xterm。每个后台终端的待回放缓冲最多保留 262,144 个字符，超出时保留较新的内容并显示截断提示。[构建实现](../../scripts/build-workbench.cjs)
3. **回归验证。** 72 项自动测试通过。隔离 VS Code 中另验证了 Bot 创建工作终端及跨标签向 Bot 投递输入，三档真实任务复测结果见上表。[修复执行记录](2026-11-27-concurrent-terminal-input.md)
